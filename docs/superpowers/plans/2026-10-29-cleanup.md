# /cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use dev-kit:subagent-driven-development (recommended) or dev-kit:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Скилл `dev-kit:cleanup` (`/cleanup`) убирает локальные ветки, чьи коммиты все на origin, разбирает stash по
одному с вопросом и делает `git worktree prune` — только через git, без знания review-kit.

**Architecture:** Один текстовый скилл `skills/cleanup/SKILL.md` по образцу `skills/gsync/SKILL.md`: нумерованные шаги
с точными git-командами, диалоги AskUserQuestion, итог таблицей. Кода в `mod/` нет. Проверка — по writing-skills:
фикстура-репозиторий со всеми случаями из спеки, прогон без скилла (RED) и со скиллом (GREEN).

**Tech Stack:** git ≥ 2.38 (`git worktree list --porcelain`, `%(upstream:track)`), Claude Code skill, AskUserQuestion.

**Spec:** `docs/superpowers/specs/2026-10-29-cleanup.md`

## Global Constraints

- Всё, что видит пользователь, — на русском; текст скилла — на английском (CLAUDE.md).
- Ссылки между скиллами — `dev-kit:<скилл>`; ни слова о `.review-kit/`, именах stash review-kit, `.claude/worktrees/`
  в тексте скилла (спека: «dev-kit не знает внутреннего состояния review-kit»).
- Ветка по умолчанию — как в gsync: `git symbolic-ref --short refs/remotes/origin/HEAD` без `origin/`, иначе `main`.
- Причины веток дословно: «удалена на origin» / «влита в <default>».
- Варианты диалогов дословно: «Удалить все (N)» / «Оставить»; для stash «Оставить» / «Применить» / «Удалить».
- Пусто → дословно «Убирать нечего».
- Никогда: удалять ветку с коммитами не на origin, текущую, ветку по умолчанию; удалять живые worktree; push, merge,
  rebase, reset.
- Пуш в `main`, меняющий плагин, поднимает `version` в `.claude-plugin/plugin.json` (CLAUDE.md) — здесь `1.0.0` → `1.1.0`.

## Решения плана (спека их не фиксирует)

- «Все коммиты на origin» — `git log <ветка> --not --remotes=origin --oneline` (спека пишет `--remotes`; fetch идёт
  только из origin, поэтому сверяемся с ним, а не с любым remote).
- Обе причины сразу → пишется одна, «удалена на origin» (она сильнее: ветку убрали на хостинге).
- «Применить» = `git stash pop` (как `stashAction` в review-kit: в уборке применённый stash больше не нужен; при
  конфликте git сам оставляет запись).
- Stash адресуется по sha: перед каждым действием индекс заново ищется в `git stash list --format=%H` — после `drop`
  индексы сдвигаются.
- «Дерево чистое» = `git status --porcelain` пуст (с неотслеживаемыми: они ломают `pop`).
- `gsync` в состоянии `[gone]` начинает ссылаться на `/cleanup` вместо `git branch -d` вручную.

## Review Focus

1. Удалён один stash, следующий адресуется по старому индексу → удалён не тот. Ожидание: действие по sha, индекс
   пересчитан (Task 2, сценарий S4).
2. `stash pop` упал с конфликтом → дальше по списку предлагается «Применить» в грязном дереве. Ожидание: итог «применён с
   конфликтом — /confl, stash сохранён», для остальных stash «Применить» уже не предлагается (S5).
3. Между диалогом и удалением в ветку попал локальный коммит → ветка удалена. Ожидание: повторная проверка, ветка в
   «пропущено: <ветка> — есть коммиты не на origin» (S6).
4. `origin/<default>` нет (пустой origin, другое имя) → `is-ancestor` падает и скилл останавливается. Ожидание: ошибка
   `is-ancestor` = «не влита», работа продолжается (S7).
5. Имя ветки со слешем (`feature/x`) и сообщение stash `On feature/x: msg` → ветка stash разобрана неверно. Ожидание:
   ветка — текст между `On `/`WIP on ` и первым `: ` (в имени ветки двоеточия не бывает) (фикстура, ветка `feature/squash`).

name: cleanup
description: Use when local git leftovers should be cleaned up (/cleanup, «убери ветки», «почисти git», «удали старые ветки») — offers to delete local branches whose commits are all on origin, goes through stashes one by one and prunes worktree records whose folders are gone. Тело — в стиле gsync: абзац запретов (раздел «Никогда» спеки + Global Constraints), затем шаги:
1. репозиторий / `git fetch --prune origin` / ветка по умолчанию — как шаги 1–3 gsync;
2. кандидаты: занятые ветки = строки `branch refs/heads/<имя>` из `git worktree list --porcelain` (покрывает текущую во

4. `git worktree prune --dry-run --verbose` до и `git worktree prune` — сколько записей убрано; про живые worktree —
   только «не трогать»;
5. ничего нет (ни кандидатов, ни stash, ни записей для prune) → «Убирать нечего», стоп;
6. диалог веток (один AskUserQuestion, список в тексте вопроса); «Удалить все (N)» → для каждой заново проверка шага 2

7. stash по одному (AskUserQuestion на запись: ветка, сообщение, возраст); «Применить» только при пустом

8. итог `| Что | Результат |`: «Ветки» — «удалено N» (+ «, пропущено: …»), по строке на тронутый stash

## Отклонения при исполнении

- Фикстура удаляет ветки в самом `origin.git`, а не `git push --delete`: тот сразу убирает и локальный `origin/<ветка>`,
  чего удаление на хостинге не делает. Поэтому до прогона `/cleanup` у веток ещё нет `[gone]` — его даёт `fetch --prune`.
- Squash-ветка после удаления на origin не проходит `git log <ветка> --not --remotes=origin` — её коммиты больше ни на
  одном ref origin. Скилл до `fetch --prune` запоминает позиции веток origin и для `[gone]`-ветки считает «все коммиты на
  origin», если она предок своей последней известной `origin/<ветка>`. Ветка, удалённая раньше (например, `/gsync`), так
  не проверяется — она не предлагается, а в итоге стоит в строке «Не тронуты» с командой для ручного удаления.
