# Переезд уборки git в dev-kit

Документ пришёл из review-kit как задача для dev-kit.

## Зачем

Сейчас `/pr cleanup` в review-kit убирает общий git-мусор: локальные ветки, stash, worktree законченных ревью. Это
общая гигиена git, а не дело ревью. Решено: уборку веток и stash перенести в dev-kit, рядом с `/gsync` и `/main`.
Review-kit убирает только то, что создал сам, и сразу (отдельный план в review-kit).

Правило dev-kit остаётся: он не знает внутреннего состояния review-kit — ни имён его stash, ни папок `.review-kit/`, ни
рабочих копий вкладок `.claude/worktrees/`.

## Что появится в dev-kit

Скилл `cleanup` (`/cleanup`, «убери ветки», «почисти git»), по образцу `gsync`. Git-команды выполняет модель по тексту
скилла, мод не нужен.

Порядок:

1. `git rev-parse --show-toplevel` упал → «Не git-репозиторий», стоп. `git fetch --prune origin` упал → вывод git,
   стоп. Ветка по умолчанию — как в gsync (`origin/HEAD`, иначе `main`).
2. Ветки-кандидаты — локальная ветка, если она:
   - не текущая, не ветка по умолчанию и не занята ни одним worktree (`git worktree list --porcelain`);
   - все её коммиты есть на origin: `git log <ветка> --not --remotes --oneline` пуст;
   - и при этом upstream удалён (`[gone]` в `%(upstream:track)`) или ветка влита в `origin/<default>`
     (`git merge-base --is-ancestor <ветка> origin/<default>`).

   Причину пишем словами: «удалена на origin» / «влита в main». Squash-merge не даёт «влита», поэтому такие ветки
   ловит только признак «удалена на origin».
3. Stash — все записи `git stash list --format='%gd|%gs|%cr'` с веткой из сообщения. Ничего не удаляется без вопроса.
4. Worktree — только `git worktree prune` (записи, чья папка уже удалена), строкой в итоге. Живые worktree не удаляются
   никогда: в них может идти чужая работа, например ревью во вкладке review-kit.

Диалоги (AskUserQuestion):

- ветки — одним списком `<ветка> — <причина>`, варианты «Удалить все (N)» / «Оставить»; удаление `git branch -D` с
  повторной проверкой «все коммиты на origin» перед каждой;
- stash — по одному: «Оставить» / «Применить» (только если дерево чистое и текущая ветка совпадает с веткой stash) /
  «Удалить» (`git stash drop`).

Итог — таблица `| Что | Результат |`: удалено веток N (пропущено: …), stash применён/удалён, worktree prune. Нечего
убирать → «Убирать нечего».

Никогда: удалять ветку с коммитами не на origin, текущую ветку, ветку по умолчанию; трогать живые worktree; push, merge,
rebase, reset.

## Что можно взять из review-kit

Логика уже есть и покрыта тестами — переносить смыслом, не файлами (в dev-kit нет API хостинга):

- `mod/git.ts`: `branchCandidates` (занятые ветки, «все коммиты на origin»), `deleteBranches` (повторная проверка перед
  `branch -D`), `reviewStashes` / `stashAction` (разбор stash list, apply / drop по sha).
- `mod/register.ts`: `offerCleanup` — порядок диалогов и формат итога.

Отличие: review-kit узнаёт «PR влит/закрыт» через API хостинга, dev-kit — только git (`[gone]` и «влита в default»).

## Порядок выпуска

1. dev-kit выпускает `/cleanup`.
2. review-kit убирает `/pr cleanup` и в README ссылается на `/cleanup` из dev-kit — это в плане гигиены review-kit.

Между шагами 1 и 2 обе команды живут параллельно и друг другу не мешают.

## Проверить в dev-kit

- Влитая ветка с удалённым upstream предлагается; ветка с локальными коммитами — никогда.
- Ветка, занятая worktree, не предлагается.
- Stash применяется только на своей ветке при чистом дереве.
- Живой worktree (`.claude/worktrees/pr-…` идущего ревью) не удаляется; prune убирает только записи без папки.
- Не git-репозиторий и упавший fetch — понятная остановка.
